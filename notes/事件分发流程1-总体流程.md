# 事件分发流程1-总体流程

## 触摸事件 -> ViewRootImpl中的InputChannel

```
 触摸事件
    |
    v
InputReader
    |
    v
InputDispatcher
    |
    | 根据WMS维护的 InputWindowInfo
    |
    v
确定目标 Window
    |
    v
通过Window对应InputChannel发送事件
    |
    v
ViewRootImpl中的InputChannel收到事件
```

### InputReader

InputReader负责读取Linux输入设备产生的原始事件，转换成Android输入系统内部事件，交给InputDispatcher处理。

### InputDispatcher
InputDispatcher收到事件以后，根据WMS负责维护的Window信息判断事件对应的目标Window，然后通过目标Window对应的InputChannel发送事件。

### InputChannel
```text
// 这里有一对InputChannel
window对应的InputChannel 
        |
        |底层基于Unix Domain Socket
        |
        V
ViewRootImpl中的InputChannel
```

这里不使用Binder传递是因为开销过大。

## WindowInputEventReceiver

当ViewRootImpl中的InputChannel收到事件以后，会回调到WindowInputEventReceiver#onInputEvent()
```java
// 关联WindowInputEventReceiver与inputChannel
mInputEventReceiver = new WindowInputEventReceiver(inputChannel,Looper.myLooper());

// 当inputChannel收到事件以后回调如下方法
public void onInputEvent(InputEvent event)
```

## ViewRootImpl中的InputChannel -> InputStage链

### InputeStage链

```text
stage1.deliver() -> stage2.deliver() -> stage3.deliver() ->..
```

你可以根据情况选择其中一个stage，然后调用它的deliver()方法开始处理事件；当某个stage处理完毕(处理完毕不等同于消费事件)事件以后 **总是** 继续调用链上的下一个stage的deliver()方法直到最后。

InputStage的实现类在onProcess()中实现主要事件处理逻辑，来产生一个“处理事件的最终结果”。当“最终结果”产生时，后续不会再有onProcess()调用产生(注意！后面的stage的deliver()
依然会被调用)。

#### onProcess()返回值

```java
// InputStage#onProcess()方法返回值
protected static final int FORWARD = 0;
protected static final int FINISH_HANDLED = 1;
protected static final int FINISH_NOT_HANDLED = 2;
```

这里我们需要拆开来看：FORWARD/FINISH/HANDLED/NOT_HANDLED

**FORWARD**:stage认为自己处理不了，调用next.onProcess()看是否有处理结果。

**FINISH**:stage对事件的处理产生了一个结果(消费/不消费)，后续的next.onProcess()没有必要再调用了。

**HANDLED**:stage处理事件的结果:消费了这个事件

**NOT_HANDLED**:stage处理事件的结果:stage发现整个stage链都没法消费这个事件

#### 继续传递的意义

首先这个执行流程是设计如此。观察源码发现，当FINISH产生时，forward()/apply()等可被子类重写的方法会被执行。我猜测这样实现(继续执行+可覆写方法)是为了给子类提供“自定义当事件处理结果产生以后执行逻辑”的功能

#### InputStage链在ViewRootImpl中真实的样子

```java
// ViewRootImpl#setView(..)
mSyntheticInputStage = new SyntheticInputStage();

InputStage viewPostImeStage = new ViewPostImeInputStage(mSyntheticInputStage);
InputStage nativePostImeStage = new NativePostImeInputStage(viewPostImeStage, "aq:native-post-ime:" + counterSuffix);
InputStage earlyPostImeStage = new EarlyPostImeInputStage(nativePostImeStage);
InputStage imeStage = new ImeInputStage(earlyPostImeStage, "aq:ime:" + counterSuffix);
InputStage viewPreImeStage = new ViewPreImeInputStage(imeStage);
InputStage nativePreImeStage = new NativePreImeInputStage(viewPreImeStage, "aq:native-pre-ime:" + counterSuffix);

mFirstInputStage = nativePreImeStage;
mFirstPostImeInputStage = earlyPostImeStage;
```

对应的InputStage链:
```text
NativePreImeInputStage(mFirstInputStage)
        ↓
ViewPreImeInputStage
        ↓
ImeInputStage
        ↓
EarlyPostImeInputStage(earlyPostImeStage)
        ↓
NativePostImeInputStage
        ↓
ViewPostImeInputStage
        ↓
SyntheticInputStage(mSyntheticInputStage)
```
ViewRootImpl会根据情况选择开始处理事件的Stage(多个地方会进行判断，如下是一处判断点)
```java
// ViewRootImpl#deliverInputEvent(..)
InputStage stage;

if (q.shouldSendToSynthesizer()) {
    // 选择1  
    stage = mSyntheticInputStage;
} else {
    // 选择2/选择3
    stage = q.shouldSkipIme() ? mFirstPostImeInputStage : mFirstInputStage;
}
```

## InputStage链处理结果 -> InputDispatcher

InputStage链的处理结果(消费/不消费)会通知给InputDispatcher。
